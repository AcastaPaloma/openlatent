# EXPERIMENTS: index of every experiment in programmes 1 and 2 (branch fields-research, 2026-11-04 to 2026-11-05)

Built only from the repository sources named in each row; numbers are copied from the builders' notes and FOCUS blocks, not recomputed. Where two sources disagree the later one is used and flagged "(see correction in ...)". Nothing here is a new claim.

## 0. How to read this (10 lines)
1. A job spec is a YAML file `research/<fields|adversarial>/jobs/specs/<job name>.yaml` (fields: name, priority, cmd, hf_path `runs/<name>`, hf_allow). The VM worker runs it; one experiment in this index may be many jobs (seeds, folds) or none (CPU re-scores of saved predictions).
2. A result dir is `research/<programme>/results/<job name>/job_result.json`: run METADATA only (exit code, seconds, commit, uploaded). It holds no metrics. Metrics live in the HF repo and in aggregates under `results/<focus>/` (f_jump, e_sc0, e_e2, h_imu, t_cxr, S, N, N2); per-unit scores are not in the repo (AUDIT_results*.md).
3. Raw outputs: Hugging Face `KuanKuanKuan/openlatent-fields`, folder `runs/<job name>` (chest X-ray `t_` jobs and the D3 `d_pii_` jobs upload only *.json, *.log, *.md; public datasets are never re-uploaded). The earlier privacy-obfuscation codebase is in `research/privacy-obfuscation` (HF `openlatent-privacy`).
4. Job prefixes. Programme 1: a_ b_ c_ d_ e_ f_ (f2_ f3_ f4_ f5_ = later JUMP/HLCA/H3-xxx work; d_pii_ = D3). Programme 2: h_ (IMU), t_ (t_s1/t_u1 stage 1, t_x T2, t_y T3, t_z T4, t_w T5/T5b, t_v T6). The charter also reserves c3_ and r_; no c3_ spec exists and the one r_ spec (r_n_cert) was withdrawn, so S and N ran outside the queue.
5. `verdict_original` = the literal pre-registered rule. `verdict_tightened` = the same rule with a tightening (never a loosening); both are printed side by side. "original = tightened" means they coincide.
6. Verdict words are quoted as written: NO-GO (a kill/gate fired as pre-registered; in D, E, F it is a GATE outcome, not a learned-arm null); NO-GO-MATCHED (floors match or beat the defence on both axes); MATCH / WIN / UNRESOLVED (per-axis labels, UNRESOLVED = interval straddles margin or power); INVALID (the test's own validity/trained/control check failed, so it is not a null); PARTIAL; FAILS (a clause or leg fails); DEAD / ALIVE-weak / MIXED (focus A); FALSIFIED; REPLICATES; SURVIVES; LEAK / BELOW_MARGIN / NOT_RESOLVED (certificate); DETECTED / MISSED (N).
7. "engagement never achieved" = an adversarial/removal term failed its pre-registered engagement gate (a fresh adversary still reads the source); the line is closed, which is NOT evidence that learned masks cannot work. "INERT TERM" = same, earlier stop rule. "lower bound" = a leakage level that a stronger attacker raises.
8. Split words: burned/development = data someone had looked at (MotionSense trials 11-16, official CXR test list, programme-1 test splits); sealed = chosen by salt after the floor list froze. "roles re-drawn over the same 4,588 patients" = T3-T6 are not independent of T2.
9. Audit tags in the Verdict column: [aud A1] Auditor-1 re-derived from raw files (fields/AUDIT_findings.md); [aud A4] Auditor-4 re-derived points/rules from results/f_jump, CIs not recomputable (fields/AUDIT_results_2.md); [aud A3] Auditor-3 reproduced arm-level values, AUCs/CIs consistency-only (adversarial/AUDIT_results.md). Auditor-2 (adversarial/AUDIT_findings.md) checked literature/licences/design before any programme-2 number. No tag = not independently re-derived.
10. Note files: `research/fields/results_notes/{A,B,C,D,E,F,JUMP0}.md`, `research/adversarial/results_notes/{H,T,S,N}.md`. Where a note has no numbered sections the heading and line number (L) are given. Every verdict is also in the FOCUS.md outcome blocks of each programme and in SUMMARY.md.
