### 2.2 Gaps the data-use gate does not catch (see F11, F12)

1. The gate allows "CC-BY / MIT IMU sets that ship user IDs" by licence CLASS. Capture-24 is CC BY and ships participant IDs, so a class rule would admit it despite its no-identification clause. The gate must be a named whitelist with a committed licence snapshot.
2. It covers inputs only. Outputs (a trained CXR linkage attacker, defended images, per-subject embeddings with IDs) are unregulated although rule 2 sends weights to HF.
3. Model licences are not gated: PriCheXy-Net is GPL-3.0 (the openlatent repo has no root LICENSE file, so nothing says how GPL code and the programme's own code relate beyond "separate process"); RAD-DINO is under the Microsoft Research licence (research only; sources conflict MIT/MSRLA, current README MSRLA); DINOv3 gated, VideoMAE CC BY-NC, TabPFN-2.5 non-commercial, HARNet academic-only (scouts). 5. Cross-dataset linkage: MIDRC's CXR subset appears to contain NIH images (CT scout); any "external set" must pass a near-duplicate check, and linkage to any outside identity is out of scope.
6. "Borderline cases go to the owner" does not say who the owner is or how clearance is recorded; H-S-001/H-CXR-001 name "Auditor-2 clearance + main agent release" as the download gate, so section 2.3 supplies it.

## 3. Findings (severity: CRITICAL blocks spend; HIGH must be fixed before the affected GPU job; MEDIUM before a claim; LOW housekeeping)

### F1 HIGH. R-IMU audits PrivDiffuser for a secret it never claimed to protect
- Evidence: arXiv 2412.14499v2 HTML (only protected attribute is gender, "identity is not a protected attribute in any experiment"; attacker trained on raw data, adversary "does not know" the data is obfuscated); README of the PrivDiffuser repo (private attribute options: gender, weight; none is identity). ObscureNet (IoTDI'21; closest arXiv match 2011.08315, a two-class gender task on MotionSense per the search summary; identity not confirmed as a target) appears to be gender-only as well. The identity-targeted published defence on exactly this dataset is the Anonymizing AutoEncoder of Malekzadeh et al. (arXiv 1810.11546: 24 MotionSense users, "activity-recognition accuracy above 92% and user-identification accuracy below 7%"), which C-AAE builds on; it is absent from FOCUS.
- Effect on FOCUS: R-IMU "Hide: user identity (NOT gender)" plus "First benchmark: PrivDiffuser ... under a retrained suite" is an off-target test. A finding "PrivDiffuser leaks identity" is a strawman; a finding that it does not would be an accident. The gender secret cannot carry a claim (24 subjects, MDE80 0.29), so the focus has no valid published claim to re-audit with the chosen defence.
- Amendment: (1) make the AAE (arXiv 1810.11546 / IoTDI'19; check code availability; re-implement from the paper otherwise) the PRIMARY identity defence, with its own published claim (<7% identity at >92% activity) as the replication target; (2) keep PrivDiffuser only as a labelled "cross-threat-model control" or retrain it with identity guidance (the existing arm B) as a learned arm, not as a re-audit; (3) write into FOCUS which published claim each defence is audited against; (4) add the AAE and its published numbers to the claim register.

### F2 HIGH. The "sealed" MotionSense and CXR test splits have already been looked at
- Evidence: contrarian_stress_test.md 4.2 reports RF/LR/LDA identity on "the last trial per subject x activity = 144 test trials" for ~12 transforms, single split, no validation split, and FOCUS derives its floor taxonomy from it ("de-meaning ... NOT floors; the floors that bite are activity-LDA codes"); H-IMU-001 then takes "fold 1 = the stress-test last-trial analogue" as the headline. I reproduced the same 144-trial numbers (section 1 row 9), so they are reproducible and therefore public knowledge inside the programme. For CXR, metadata floors and the matched-negative numbers (0.843 / 0.900) were computed on the official test list and PriCheXy's 5,000 test pairs.
- Effect: programme-1 lesson "select on validation, never on the sealed test; disclose anything seen early" is violated for the headline split; floors, matching calipers and transforms were chosen with test-set sight. The certificate's "sealed" claim is false for these splits.
- Amendment: add a "burned-set ledger" to FOCUS: MotionSense trials 11-16 (last trial) and the official CXR test list / PriCheXy 5,000 pairs are DEVELOPMENT sets. Re-seal with a fresh partition drawn by hash with a salt committed AFTER the floor list is frozen (e.g. rank folds by sha256(subject|activity|salt), CXR: a 5-fold patient hash over the 13,302 multi-visit patients, which H-CXR-002 already uses, but the headline must be a fold no one has looked at), or move the sealed claim to WISDM/UCI-HAR. Report burned-split numbers as exploratory.

### F3 HIGH. Released checkpoints cannot be cross-fitted; clean power is 96 trials, not 144 or 360
- Evidence: PrivDiffuser loader: train trials 1-9 (dws 1,2; ups 3,4; wlk 7,8; jog 9), test trials 11,12,15,16; sit/std absent from its design. H-IMU-001 arm A releases "all 360 trials" through the released checkpoint with 3 rank folds and calls the contamination "window-level split ... effect on identity unknown". In fact trials 1-9 are the checkpoint's TRAINING data (a diffusion model can reproduce training windows), so rank folds 1-2 test the defender on its own training trials, and std/sit are out of its training distribution. H-CXR-001 itself notes the same issue for PriCheXy ("released weights were trained on its train patients so rotation would leak").
- Effect: seeds and rotation do not buy test power for any released defender, contradicting the cross-fit promise in CHARTER ("every pre-registration names its seeds-vs-test-units design"). Clean arm-A n = 24 x 4 = 96 trials, paired MDE80 about 9-13 points (SE sqrt(0.12*0.88/96) = 3.3 pts; x2.8; larger with subject clustering) versus a 3-point margin.
- Amendment: restrict arm A to trials 11,12,15,16 (4 activities, 96 trials), print the MDE next to every difference, and say arm A can only resolve gaps >= 10 points; use cross-fit only for defenders retrained inside the programme (AAE, arm B, floors). For CXR: use the released PriCheXy weights only on the PriCheXy test patients, and fold-rotate only the retrained floors/attackers.

### F4 HIGH. R-CXR needs a three-way patient split and an unbiased pair design; neither is pre-registered
- Evidence: PriCheXy trains its attacker "by using deformed images only" from the SAME train patients its generator was fit on; LAPIS keeps D_mod (defender), D_rel (release/attacker) and D_test disjoint. In PriCheXy's own 5,000 test pairs, 492 patients supply all 2,500 positives (about 5 positives each, median follow-up-index gap 17; `cxr_pairs.py`), 24% of positive pairs mix PA/AP views and 42% mix original image dimensions, so pairs are not independent patients and the positives come from heavily imaged patients (7,123 of 13,302 multi-visit patients have both views). Pixel spacing and dimensions in the CSV are of the ORIGINAL images; the released PNGs are described (H-CXR-005, not checked here) as 1024 x 1024 resamples, so an image-only attacker may still recover aspect-ratio/acquisition cues.
- Effect: an attacker trained on defended images of patients the defender memorised is not the attacker a releaser faces (direction of bias unknown); inflated pair counts overstate precision; the "1,424 patients" in FOCUS is the right unit only if one pair per patient or a patient-cluster bootstrap is used (the stress test does the latter, FOCUS does not say so).
- Amendment: pre-register (i) defender-train / attacker-train / sealed-test as three patient-disjoint sets, with attacker-trained-on-defender-seen-patients reported as a sensitivity arm; (ii) one positive and one matched negative per patient (or patient-cluster bootstrap, B >= 2000); (iii) strata for view mix, original-dimension mix and follow-up gap; (iv) the number of multi-visit patients available to each role (the 13,302 split three ways leaves the attacker pool well below the 1,424-test comfort zone: say it).

### F5 HIGH. Kill rules in FOCUS are not checkable, the stage-0 gate is not in FOCUS, and several controls have no tolerance
- Evidence: FOCUS R-CXR "Kill: if the floor envelope matches every learned defence at matched linkage AUC over 3 seeds with cross-fit, or if the demographic attacker explains the whole signal"; R-IMU "if the activity-LDA floor matches the learned obfuscators at matched identity accuracy, or if 24 subjects cannot resolve the margin". "Matches", "matched", "explains the whole signal" have no margin, CI rule, direction or matching procedure. The stress test's stage-0 kill ("real-image matched-negative AUC does not exceed the metadata floor by >= 0.03") and the hypotheses' falsifiers live only in H-*.md, not in the locked FOCUS. "Every learned defence" is a population of one (PriCheXy-Net at three mu), so a tie cannot support a statement about learned defences in general. "Controls at chance" has no numeric tolerance. Programme-1 Focus F was decided literally on a control clause whose tolerance (0.01) was smaller than the control's own design bias (0.042-0.045), and Focus E's "3x chance" threshold misfired at high chance.
- Amendment: add to FOCUS a pre-registration template with machine-checkable fields: comparator list (frozen), matching rule (e.g. "floor point = linear interpolation of the lower envelope at the learned point's worst-suite leakage, both axes with CI"), margin delta fixed from the printed MDE, verdict rule as an inequality on the lower/upper 95% CI bound of (floor - learned), control tolerance = max(1.96 SE of the control, design-effect-aware MDE), the stage-0 gate copied from the stress test, a statement of how many distinct learned defences exist, and fields `verdict_original`, `verdict_tightened` as required in result.json. State that the result generalises only to the defences tested.

### F6 MEDIUM-HIGH. H-CXR-002 rests on a premise the programme contradicts; MN-v1 is defined in a way that can create an inverse shortcut
- Evidence: H-CXR-002 "Mechanism": Packhauser's 0.994 AUC "cannot be demographics", prior 0.85, predicted gap >= 0.30. Age + sex alone give 0.983-0.984 on random negatives (stress test, reproduced in section 1 row 3), so 0.994 exceeds the metadata line by about 0.01. MN-v1 (H-CXR-001): "identical (Width, Height, PixelSpacing)" for ALL negatives, but only 58% of PriCheXy's positive pairs share dimensions (`cxr_pairs.py`: 0.5796), so "different device" becomes evidence FOR the positive class; the stated validity gate (GBM on true metadata <= 0.56) would catch it only after the fact. Separately the stress test measured 0.843 (true age + sex) on negatives matched only to |age gap| <= 3 y, which shows that caliper-style matching leaves signal; MN-v1's "match the positive's age gap within +-1 y" is better but unverified.
- Effect: the 0.85 prior is unjustified and the stage-0 gate (>= 0.03 above the metadata line) is the real test; a pass on a leaky MN-v1 would be a false positive for "identity beyond demographics".
- Amendment: define matching on the PAIR-feature distribution (same-view flag, same-dimension flag, same-spacing flag, age gap, sex) so that each stratum has matched positive and negative frequencies; require a validity gate with CIs before any image model is trained (true-metadata GBM, device-only GBM and border-only CNN all <= 0.56 on MN-v1); lower the prior on H-CXR-002 to about 0.6 and fix its mechanism text.

### F7 MEDIUM. Static-window identity is already measured at 48%: H-IMU-006's premise is falsified before it runs, and MotionSense identity is not "gait"
- Evidence: `ms_repl.py` (RF, same protocol as the stress test, held-out trials 13 and 14 = sit and std, 48 test trials, chance 4.2%): static activities, rotationRate + userAcceleration, de-meaned per window: 47.9%; all 12 channels incl. means 33.3%; attitude + gravity means only 31.2%; dynamic activities de-meaned: 91.7% (96 trials). H-IMU-006 predicts (C) <= 12% and states it is FALSIFIED if >= 25%. Single seed, 48 trials (SE about 7 pts), but the margin is far larger than that.
- Effect: a resting phone in a pocket identifies the wearer at about 11x chance after removing means, so identity here includes non-gait signal (sensor noise, tremor/respiration, placement-dependent noise, session state), the IMU analogue of CREMA-D's 76% channel signal. The stress-test line "identity is per-user amplitude statistics of gait" is not established, and a defence's gain on dynamic windows may leave the static channel untouched.
- Amendment: report every IMU result stratified static / dynamic; rewrite H-IMU-006 as a measured premise with a new falsifier (what remains after band-limiting, sensor-noise whitening, or spectral flattening) and add it to the mandatory controls of R-IMU; word every claim "same-session identity (gait + posture + sensor state)".

### F8 MEDIUM. The locked focus no longer tests the charter's first falsifiable clause
- Evidence: CHARTER "Falsifiable core: a standardised suite whose worst case moves the conclusions of programme 1's HAR results, or a defender trained against a suite that generalises". FOCUS R covers external IMU/CXR defences; programme-1 video re-attack is "optional" in the stress test and absent from FOCUS; G is conditional with an expected 15% pass rate.
- Effect: the most likely outcome (R-IMU resolves only >= 10-point gaps, G closed) would leave the charter question about programme 1 unanswered.
- Amendment: name a zero-GPU deliverable in S: re-score programme 1's stored `preds.npz` (KTH, UTD-MHAD, Charades, HMDB51) with the sealed-suite machinery (cluster bootstrap, best-of-K, evidence budget) and state per release whether the programme-1 verdict moves by more than the printed MDE; add 1-2 new attacker families on KTH only if that step shows headroom.

### F9 MEDIUM. Evaluator integrity and scorer gaming by agents
- Evidence: `src/s_suite/certificate.py` binds a suite declaration digest into the output, but (a) the output carries only `VERSION = "s_suite/1"`, no git SHA or file hash of the evaluator; (b) nothing ties the digest to a committed pre-registration or enforces that the pre-registration commit precedes the first sealed number; (c) nothing limits sealed-split queries (a builder can rerun with another seed/config and read `result.json`, i.e. the sealed test acts as a validation set); (d) the same agent family writes hypotheses (self-assigned priors), the suite, the planted leaks and the verdict function; (e) tick loops show interim results to the main agent, so optional stopping is possible.
- Amendment: freeze the evaluator by git tag + sha256 recorded in the pre-registration and printed in every certificate; a sealed-query ledger (release digest, split, timestamp) kept outside builder-writable directories and refusing a second sealed query for the same release digest unless a declared amendment exists; CI/script check that `prereg_commit` is an ancestor of the commit that produced the first sealed number; priors for hypotheses assigned or reviewed by someone other than the author; declare primary endpoints (see F18).

### F10 MEDIUM. Planted-leak calibration measures the instrument against leaks it was built to find
- Evidence: `src/s_suite/planted.py`: planted channels (bias, gain, spectral line) map one-to-one onto the attackers' hand features (mean, std, band energies); toy geometry (T=32, 4 channels, W=4 windows, 25 identities); the oracle is a key-aware matched filter written by the same builder. H-S-001 plants into donor-swapped real windows but the planted types are again the ones the suite's features read. The defender never sees the planted leak (good), but the suite builder chooses both leak and detector.
- Effect: detection of dialled leaks is guaranteed by construction; the minimum detectable dose says little about unknown real leaks, and the "blind spot" prediction is the only informative part.
- Amendment: a negative-control builder (section 5) who owns a sealed manifest of planted leaks, with at least two leak families the suite builder has not seen (cross-channel phase coupling, nonlinear amplitude-frequency interaction, a stealth leak encoded in a band the declared features do not read), injected into REAL defended releases; report detection vs dose including the miss rate for the unseen families; run the identical planted-leak procedure on the shuffled-label search loop.
