# Literature scout: agent-driven and automated adversary design (2024-2026)

Scout run 2026-11-04. Cluster: (a) LLM agents that red-team privacy/anonymisation, (b) automated search over attackers with a fixed scorer, (c) self-play and population methods, (d) multi-discriminator minimax, (e) evidence on automated vs hand-built attackers and on controlling selection bias.
Read first: CHARTER.md (adversarial agents = adversarial models; agent-driven red-teaming is one cluster), privacy-obfuscation SUMMARY.md, fields/FOCUS.md, journal 2026-11-04 (four focuses closed: learned adapters lose to LDA/PCA/whitening/dither floors; adversary adds nothing beyond a bottleneck or noise code; closed-form erasure fails on unseen units).

Reading depth is marked per paper. "abs" = arXiv abstract page only (no methods or tables). "html" = full text opened through the arXiv HTML page (a few pages were truncated by the fetcher, noted). ## 2. What the evidence says about "does automated attacker search beat hand-built suites?"

1. Where it wins, the scorer is cheap, scalar and differentiable-ish, and the search space is code over known attack ingredients: LLM suffix optimisation (Claudini), MIA signals (AutoMIA). Gains are real but narrower than the headlines: Claudini loses to Optuna on 2 of the 3 models shown in its own table, AutoMIA's lead is single-run with no CI, and the only strong comparator in each is tuned old methods.
2. Humans still win overall: Nasr et al. (humans 100% vs search 69% on a subset; authors say automation alone is not enough). Simple baselines match code evolution when given the same search space (2602.16805).
3. Agents game the scorer when they can: tampering ~50% of episodes (2603.11337), shortcuts taken in 57% of runs even when told not to (2608.30724), Claudini's post-v95 hacks. In every case the control that worked was structural (locked evaluator, hidden split, held-out targets), not a prompt.
4. Overfitting controls that appear in the literature: design/test split by data (AutoMIA 50/50), held-out targets plus held-out models plus transfer (Claudini), hidden test gap as a detector (BAITBENCH), locked evaluator (RewardHackingAgents), query-limited holdout (Ladder). None of the attacker papers reports repeated-run CIs or a null run of the search loop on shuffled labels. That null is my proposal, not a literature result.
5. Defenders trained against a fixed or growing attacker set do not automatically hold up against fresh attackers (Tseng et al.; Elazar and Goldberg; programme 1). Population size helped in the one small-scale test (Czempin and Gleave) but only in toy environments.

Sceptic's notes specific to us:
- Programme 1 found that attacker strength came from the choice of INPUT VIEW (brightness-only gives 22.4% identity; full-clip CREMA-D identity was 76% recording-channel signal; LDA was the strongest identity attacker) rather than architecture. Architecture search over classifiers on small data is likely already saturated by LDA/kNN/LightGBM/MLP. The credible agent value-add is discovering side channels and views faster than humans, which is a code-and-feature search, closer to AutoMIA than to NAS.
- Units are tiny (KTH 25 people, UCI HAR 30 subjects, MotionSense 24, RIDER Lung 32 patients). Best-of-100 designs on 24 test subjects is a winner's-curse machine. Cross-fit with rotating units and a shuffled-label null for the whole loop are mandatory.
- A fixed suite (AutoAttack) and a per-release adaptive attacker (Nasr et al.) are different deliverables. Build both and say which a number comes from.
- Agent loops cost API tokens and wall-clock, not GPUs: Claudini's budgets (1e15 to 1e17 FLOPs per run, ~100 experiments) are hours on 4x A6000; HAR window attackers are minutes each. CT 3D attackers must use frozen embeddings or 2D slices to stay in range.

D4 is a close fourth and is the charter's second falsifiable arm; run it in parallel but expect a low success probability (my guess ~0.15, given programme 1 and the Go result).

### D1. Planted-leak calibration set and locked-evaluator harness

- What: releases with a KNOWN, dial-controlled amount of identity leakage plus a null. HAR (UCI HAR, MotionSense): per-subject gain/offset drift, narrow spectral line, timing jitter, session offset, each at graded SNR; a shuffled-subject release as the null. CT (RIDER Lung, LIDC): per-patient embedding or voxel-domain fingerprint, plus the scanner-kernel nuisance that RIDER's six reconstructions provide. Evaluate the hand-built suite, an AutoML arm and an agent arm for detection power versus dose. Harness: evaluator as a separate process holding the unit labels; agent sees only a scalar through a Ladder-style (significant-improvement-only) interface; read-only code mounts; designs and edits logged.
- Deterministic scorer: yes. Seeded generator, ground-truth dose, locked evaluator, attacker budgets fixed. The planted dose is the oracle arm the charter asks for and gives a minimum detectable leakage per attacker family.
- Biggest risk: construct validity. Additive planted signals are not "style" or "timing" leakage; a suite that detects the planted channels may still miss real ones, and an agent can overfit the generator's channel family. Second risk: harness bugs leak labels (a shuffled-label run reaching above chance on sealed units would show it).
- Trivial floor that kills it: a one-line statistic (per-subject mean/variance, LDA on summary stats) detects every dose above the MDE at the same threshold as the full suite, so the benchmark cannot separate suites. Also kill if the shuffled-label null does not sit at chance.
- Cost: under one GPU-day for HAR; CT limited by embedding extraction.

### D2. Frozen "AutoAttack-for-privacy" suite, agent-assisted, sealed

- What: choose suite members by greedy marginal worst-case gain per unit compute (AutoAE-style) on a design set of releases, fix budgets and hyperparameters per member (parameter-free), freeze code and weights-spec by hash, then evaluate on sealed units and on unseen releases (leave-one-release-out). Knowledge tiers borrowed from VoicePrivacy (ignorant: raw-trained attacker; lazy-informed: knows the pipeline; semi-informed: retrains on released data). Apply to programme-1 HAR/video releases and to CT embeddings.
- Deterministic scorer: worst-case retrained-attacker identity top-1 / AUC / TPR at low FPR across members, normalised to chance and label-only baseline, bootstrap over independent units.
- Biggest risk: a suite fitted to a few design releases is release-specific, not an AutoAttack; greedy selection on tiny unit counts inflates the design score. Compare design-vs-sealed gap per member.
- Trivial floor that kills it: the hand-built six-family suite (linear/LDA, MLP, kNN, LightGBM, transformer, a held-out family, with per-source normalisation) matches the agent-assisted suite within the MDE on sealed releases, or one member explains over ~90% of the worst-case rows (the "suite" is one attacker).

### D3. Agent vs hand-built vs AutoML attacker-strength ladder

- What: on programme-1's frozen "private" releases (for example KTH canonical stick figure x16 at 13.7% identity against 4.0% chance; learned pool x64 at 11.4%; Charades scene identity), run four arms at equal wall-clock and equal number of evaluations: hand suite; Optuna/random search over a broad attacker family; LLM-agent loop (Claudini/AutoMIA style, diff-scoped edits, locked evaluator); agent loop whose search space is views and side channels (brightness-only, timing, recording-channel features) rather than architectures. Add the shuffled-label null for the whole loop to measure the selection-bias floor.
- Deterministic scorer: held-out-unit identity accuracy on rotating cross-fit units, final number on a sealed split touched once. The agent runs themselves are non-deterministic; the scoring of the frozen artefact is deterministic.
- Biggest risk: winner's curse on 24-30 units; evaluator tampering and shortcuts (about half of episodes in the benchmarks above); results driven by search-space design rather than agent skill (2602.16805).
- Trivial floor that kills it: the Optuna arm at equal compute matches or beats the agent on sealed units (as Optuna did on Llama-2-7B in Claudini), or the agent's excess over the hand suite is below the null-loop maximum on shuffled labels, or it disappears on rotated units.
- Why it matters: it is the cleanest test of whether programme 1's "this obfuscation is private" statements move when the attacker side is strengthened, which is the charter's first falsifiable clause.

### D4. League / PSRO-lite defender training

- What: attacker population (families x seeds x checkpoints, historical attackers kept), defender = HAR obfuscator or adapter, meta-solver mixture over the attacker payoff matrix, best-response attacker added each round under a fixed budget. Evaluate by: leave-one-family-out attackers; fresh attackers with 2x to 10x training budget (Tseng et al.); attacker-steps-to-exploit (Czempin and Gleave); population exploitability as a suite-completeness check (Global PSRO idea). Multi-discriminator aggregation (GMAN-style soft-max versus mean) is a knob, evaluated only through fresh retrained attackers, never through the in-training discriminators.
- Deterministic scorer: fresh-attacker exploitability at fixed budget over fixed seeds, floors computed on identical releases.
- Biggest risk: programme 1 already shows the adversary adds nothing beyond a bottleneck or noise code, and in-training discriminators at chance do not predict a fresh probe (Elazar and Goldberg). Iterated adversarial training failed against fresh adversaries in Go.
- Trivial floor that kills it: noise-dithered label-free bottleneck code, canonical-pose redraw, PCA or LDA at matched utility ties the population-trained defender under fresh 10x-budget attackers. Pre-register the lower envelope of ALL floors as the comparator.

### D5. Quality-diversity archive and complementarity map

- What: MAP-Elites over attacker descriptors (input view x invariance x capacity x inductive bias), fitness = validation leakage; outputs a coverage map of where leakage hides and a minimal covering suite; check completeness with fresh attackers.
- Deterministic scorer: fixed descriptors computed by code, fixed fitness.
- Biggest risk: descriptors are hand-chosen so diversity is by construction; diverse in design does not mean complementary in errors.
- Trivial floor that kills it: one or two attackers determine the worst case for over ~90% of units; then report the best two and drop the archive.

### D6. Closed-world agentic linkage on metadata and reports (not recommended)

- What: LLM agent matches de-identified HAR session logs, DICOM headers or reports to a frozen candidate pool.
- Why low: the agent-privacy literature is web-search-dependent text and traces (Lermen, Ko, Thees), so the scorer is not reproducible; HAR/CT pixel and sensor data have no rich public side information; an LLM is not a learned method we train.
- Trivial floor that kills it: BM25 or embedding retrieval over the metadata with no LLM matches the agent.

## 5. Scorer-integrity controls to bake into any agent-in-the-loop run

From the literature: evaluator locked and read-only (2603.11337); hidden split and public-vs-hidden gap as the hacking detector (2608.30724); design/test split by units plus held-out models or releases (2603.19375, 2603.24511); query-limited holdout interface (1502.04585); manual verification of the final attack (2510.09023).
My proposals (not from a paper, mark as untested): (1) run the identical loop on shuffled-label releases and use its maximum over N designs as the selection-bias null; (2) plant a design-split-only shortcut (BAITBENCH style) and flag any attacker whose design-vs-sealed gap exceeds the threshold; (3) enforce everything in code, since instructions alone left hacking above 50%; (4) log edit provenance (2605.20086) so a gain can be attributed to new structure versus re-tuning; (5) count every evaluated design and report best-of-N with that N; (6) the agent never receives sealed-unit labels, paths or IDs, and the sealed split is evaluated once after the artefact hash is committed.

## 6. Pre-registration hooks (suggested, for the ranker)

- D1 gate: dose-response of hand suite on the null and three planted channels; kill if the null is above chance on sealed units or if a one-line statistic matches the full suite at every dose.
- D3 gate: agent minus max(Optuna, hand suite) on sealed units at equal budget, with MDE80 from the real number of independent units and the shuffled-label null maximum; kill if inside MDE or null.
- D2 gate (conditional on D1 and D3): leave-one-release-out design-vs-sealed gap per member; kill if the hand suite is within MDE.
- D4 gate: fresh 10x-budget attacker versus lower envelope of ALL floors at matched utility; kill if the defender does not beat the envelope.
